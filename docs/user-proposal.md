# 제주 관광 소비 인사이트 Agent 기획서

Nov 19, 2026 · @남예원

## 1. 구현 목표

제주 관광 소비 인사이트 Agent는 자연어 질문 하나로 제주 관광 카드 소비 데이터를 분석하고, 수치 근거와 실행 제안이 담긴 보고서를 만들어 주는 AI Agent입니다.

### 1.1 해결하려는 문제

제주의 관광 소비 데이터는 공개되어 있지만, 데이터 분석 경험이 없는 사용자가 의사결정에 바로 활용하기는 어렵습니다. 어떤 데이터를 골라 어떻게 집계하고, 결과를 어떻게 해석할지가 모두 진입장벽입니다.

| 대상 사용자 | 현재의 어려움 | Agent가 제공하는 가치 |
| --- | --- | --- |
| 제주 소상공인·예비 창업자 | 주 고객층과 성수기를 경험에 의존해 판단 | 지역·업종·고객층별 소비 분석과 프로모션 시기 제안 |
| 제주빅데이터센터 이용자 | 데이터 탐색과 집계 코드 작성에 시간 소요 | 질문만으로 데이터 선택, 집계, 시각화까지 자동 수행 |
| 행정·관광 실무자 | 현황 보고용 기초 분석을 반복 작성 | 출처와 산출 근거가 포함된 분석 보고서 초안 생성 |

### 1.2 분석 주제

핵심 분석 주제는 "제주 관광객의 소비가 언제, 누구에 의해, 어디서, 어떤 업종에 집중되는가"입니다.

| 분석 관점 | 분석 질문 | 분석 방법 |
| --- | --- | --- |
| 시기 | 소비가 많은 달과 요일은 언제인가 | 월별 추세, 전년 동월 대비 증감, 요일별 비교 |
| 고객층 | 어떤 연령대와 성별의 소비 비중이 높은가 | 인구 집단별 이용금액 비중, 1인당 이용금액 |
| 지역 | 어느 지역과 지구에 소비가 집중되는가 | 시군구·지구별 순위와 비중 |
| 업종 | 어떤 업종과 테마가 성장하고 있는가 | 업종·테마별 순위와 증감률 |

### 1.3 AI 활용 데이터 분석 목표

LLM은 질문 해석, 분석 계획 수립, 결과 해석을 맡고 모든 수치 계산은 검증 가능한 코드가 수행합니다. 이렇게 역할을 나누면 LLM이 수치를 잘못 만들어 낼 위험을 구조적으로 줄일 수 있습니다.

| 목표 | 평가 지표 | 목표치 |
| --- | --- | --- |
| 질문 조건을 정확히 해석 | 지역·업종·고객층·기간 추출 정확도 | 90% 이상 |
| 알맞은 데이터와 분석 도구 선택 | 평가 질문별 도구 선택 정확도 | 90% 이상 |
| 보고서 수치의 정확성 확보 | 원본 데이터 재계산 결과와의 일치율 | 100% |
| 판단 과정의 투명성 확보 | 판단 로그가 기록된 실행 비율 | 100% |

목표치는 30개 질문으로 구성한 자체 평가셋으로 측정하고, 측정 결과는 최종 결과물의 결과 설명자료에 수록합니다.

### 1.4 기대효과

| 구분 | 기존 방식 | Agent 활용 |
| --- | --- | --- |
| 데이터 탐색 | 사용자가 직접 데이터를 찾고 항목을 확인 | Agent가 질문에 맞는 데이터를 자동 선택 |
| 분석 | 스프레드시트나 코드로 직접 집계 | 자연어 질문으로 집계와 시각화 수행 |
| 신뢰성 | 작성자에 따라 산출 근거가 달라짐 | 출처, 조건, 계산 결과를 보고서에 함께 표기 |
| 활용 | 분석 결과를 의사결정 언어로 다시 해석 | 사용자 상황에 맞는 실행 제안까지 제공 |

## 2. 서비스 제안

사용자는 데이터나 코드를 몰라도 웹 화면에 질문을 입력하는 것만으로 분석 보고서를 받을 수 있습니다.

### 2.1 데이터 활용 개요

월간 관광객 카드 사용 데이터로 고객층·업종·지역을 분석하고, 요일별 카드 데이터로 구체적인 실행 시점을 보완합니다. 두 데이터의 상세 항목은 4장에 정리했습니다.

### 2.2 사용자 이용 흐름

1. 사용자가 화면에 질문을 입력하거나 예시 질문을 선택합니다.
2. 조건이 부족하면 Agent가 지역, 업종, 기간 등을 되묻습니다.
3. Agent가 데이터를 선택하고 분석하는 과정을 화면에 단계별로 표시합니다.
4. 사용자가 핵심 요약, 차트, 수치 근거, 실행 제안을 확인합니다.
5. 추가 질문으로 분석을 이어가거나 보고서를 내려받습니다.

> **예시 질문:** "서귀포시에서 30대 관광객을 대상으로 식음료 프로모션을 하려면 언제가 좋을까?"

### 2.3 핵심 기능

| 기능 | 설명 | 사용자 이점 |
| --- | --- | --- |
| 자연어 질의 | 일상 언어로 질문하면 분석 조건을 자동 추출 | 데이터 지식 없이 이용 가능 |
| 조건 확인 | 모호하거나 빠진 조건을 사용자에게 되물음 | 의도와 다른 분석 방지 |
| 자동 분석 | 추세, 순위, 비중, 증감률을 코드로 계산 | 일관되고 재현 가능한 결과 |
| 결과 검증 | 수치 재계산, 표본 크기 점검, 필요 시 재분석 | 신뢰할 수 있는 근거 확보 |
| 보고서 생성 | 요약, 차트, 근거, 실행 제안, 한계를 정리 | 바로 공유하고 활용 가능 |
| 판단 로그 | 도구 선택 이유와 실행 과정을 기록 | 분석 과정을 검토 가능 |

### 2.4 편의성

- **설치 부담 최소화:** Windows에서 실행 파일로 설치와 구동을 처리합니다.
- **진행 상황 표시:** Agent가 수행 중인 단계를 화면에서 바로 확인합니다.
- **예시 질문 제공:** 처음 쓰는 사용자도 클릭 한 번으로 시작합니다.
- **이해하기 쉬운 결과:** 전문 용어를 줄이고 결론부터 제시합니다.

### 2.5 분석 데이터 활용 방안

| 활용 분야 | 활용 예시 | 사용하는 분석 결과 |
| --- | --- | --- |
| 상권 분석 | 창업 예정 지역의 업종별 소비 규모 파악 | 지역·업종별 순위, 증감률 |
| 마케팅 | 주 고객층과 성수기에 맞춘 프로모션 기획 | 연령대·성별 비중, 월·요일별 추세 |
| 관광 정책 | 지역별 소비 편중 현황 파악 | 시군구·지구별 소비 비중 |
| 센터 교육 | 데이터 분석 입문자의 실습 도구로 활용 | 판단 로그, 집계 과정 |

## 3. Agent 개발 구성

Agent는 질문 해석부터 보고서 생성까지 스스로 수행하되, 검증을 통과한 결과만 사용자에게 제공합니다.

### 3.1 역할과 목표

| 주체 | 역할 | 목표 |
| --- | --- | --- |
| 참여자 | 문제 정의, 데이터 선정, Prompt·Tool 개발, 평가 기준 수립, 결과 검수 | 센터에서 실행 가능한 Agent 완성 |
| Agent | 질문 해석, 분석 계획, 도구 실행, 결과 검증, 보고서 생성 | 근거가 확인된 분석 결과 제공 |
| 사용자 | 질문 입력, 추가 조건 답변, 최종 의사결정 | 분석 결과를 사업·정책 판단에 활용 |

### 3.2 Workflow

&#91;embedded content: Agent Workflow · 5단계, 판단 지점 2곳\]

조건이 부족하면 사용자에게 되묻고, 검증 기준에 미달하면 분석 계획으로 돌아가 최대 2회 재분석합니다. 재분석 후에도 기준에 미달하면 한계를 명시해 결과를 제공합니다.

### 3.3 사용 모델

| 구분 | 내용 |
| --- | --- |
| LLM | Anthropic Claude Opus 5.5 (`claude-opus-5-5`) |
| 호출 방식 | Anthropic Messages API의 Tool Use 기능과 자체 Agent 루프 |
| LLM 담당 | 질문 해석, 분석 계획 수립, 도구 선택, 결과 해석, 보고서 문장 작성 |
| 코드 담당 | 데이터 조회, 집계, 증감률 계산, 검증, 차트 생성 |
| Prompt 구성 | 역할 정의, 데이터 설명, 도구 사용 원칙, 수치 작성 규칙, 보고서 형식 |

### 3.4 Tool/API

| Tool | 기능 | 입력 | 출력 |
| --- | --- | --- | --- |
| `list_datasets` | 사용 가능한 데이터와 항목, 기간 조회 | 없음 | 데이터 목록, 항목, 기간 |
| `query_spending` | 조건별 필터링과 그룹 집계 | 데이터, 조건, 그룹 기준 | 집계표 |
| `analyze_trend` | 월별 추세와 전년 동월 대비 증감 계산 | 조건, 기간 | 추세표, 증감률 |
| `rank_segments` | 지역·업종·고객층 순위와 비중 계산 | 조건, 순위 기준 | 순위표, 비중 |
| `verify_result` | 원본 재계산, 조건 일치, 표본 크기 점검 | 분석 결과 참조 ID | 통과 여부, 경고 |
| `create_chart` | 분석 결과 시각화 | 분석 결과 참조 ID, 차트 유형 | 차트 이미지 |
| `build_report` | 검증된 결과로 보고서 구성 | 요약, 근거, 제안 | 보고서 파일 |

### 3.5 판단 및 자율 수행 범위

| 구분 | 범위 |
| --- | --- |
| Agent가 자율 수행 | 데이터와 도구 선택, 분석 순서 결정, 표본 부족 시 조건 조정, 최대 2회 재분석, 차트 유형 선택 |
| 사용자 확인 필요 | 지역·업종·기간이 모호한 경우, 질문의 의도가 둘 이상으로 해석되는 경우 |
| 사람이 최종 판단 | 프로모션 실행, 창업, 정책 결정 등 실제 의사결정 |
| 수행하지 않음 | 데이터 원본 수정, 개인 식별 시도, 데이터에 없는 수치 생성, 외부로의 자동 게시 |

### 4.3 수집 방법

1. 제주데이터허브에서 데이터를 내려받거나 API로 수집합니다.
2. 수집한 원본을 `data/raw/`에 별도로 보관하고 수정하지 않습니다.
3. 전처리 결과를 `data/processed/`에 저장해 실행 중 네트워크 의존성을 줄입니다.

API Key는 제출물에 포함하지 않고, 발급과 설정 방법을 실행 매뉴얼에 안내합니다.

### 4.4 전처리 방법

| 단계 | 처리 내용 | 검증 방법 |
| --- | --- | --- |
| 스키마 점검 | 필수 항목 존재와 자료형 확인 | 누락 시 오류 메시지 출력 |
| 형식 통일 | 날짜, 숫자, 지역·업종 표기 표준화 | 변환 전후 건수 비교 |
| 결측치 처리 | 핵심 항목 결측 행을 분석에서 제외하고 건수 기록 | 제외 건수 로그 저장 |
| 중복 제거 | 동일 키의 완전 중복 행 제거 | 제거 건수 로그 저장 |
| 이상치 점검 | 음수 금액과 비정상 값 확인 | 원본 값은 유지하고 경고 표시 |
| 파생 변수 생성 | 연도, 월, 1인당·건당 이용금액 계산 | 표본 재계산으로 일치 확인 |

### 4.5 개인정보 보호

활용 데이터는 지역·업종·연령대 단위로 집계된 통계이며 개인 식별 항목을 사용하지 않습니다. 이용자 수가 적은 세부 집단은 결과에 경고를 표시하고 상위 범주로 통합합니다.

## 5. 개발·탑재 계획

Agent는 센터 운영 PC에서 Python 웹 앱으로 실행되고, 외부 서비스는 LLM API 하나만 사용합니다.

### 5.1 구현 범위

## 6. 검증, 한계 및 센터 활용 방안

보고서의 모든 수치는 원본 데이터로 재계산해 검증하고, 검증할 수 없는 한계는 사용자에게 명시합니다.

### 6.1 검증 방법

| 검증 단계 | 검증 내용 | 통과 기준 |
| --- | --- | --- |
| 실행 중 수치 검증 | 분석 결과를 원본 데이터로 독립 재계산 | 오차 없이 일치 |
| 실행 중 조건 검증 | 질문 조건과 실제 필터 조건 비교 | 지역·업종·고객층·기간 일치 |
| 실행 중 표본 점검 | 분석 대상 건수와 이용자 수 확인 | 기준 미달 시 경고 또는 재분석 |
| 보고서 수치 검증 | 보고서 문장의 수치와 분석 결과 대조 | 분석 결과에 없는 수치 미포함 |
| 종합 성능 평가 | 30개 평가 질문으로 1.3절의 지표 측정 | 1.3절의 목표치 달성 |

평가 질문은 단순 조회, 비교·추세 분석, 조건이 모호한 질문, 데이터로 답할 수 없는 질문을 고루 포함합니다.

### 6.2 한계 및 대응 방안

| 한계 | 영향 | 대응 방안 |
| --- | --- | --- |
| 카드 소비 데이터만 분석 | 현금 등 다른 결제 수단은 반영되지 않음 | 보고서에 분석 범위를 명시 |
| 내국인 관광객 중심 데이터 | 외국인 관광객 소비는 설명하기 어려움 | 분석 대상을 명시하고 답변 범위를 제한 |
| 상관관계 중심 분석 | 실행 제안의 인과 효과를 보장하지 않음 | 제안을 참고용으로 표기하고 최종 판단은 사람이 수행 |
| 세부 집단의 표본 부족 | 결과의 변동성이 커질 수 있음 | 경고 표시 후 상위 범주로 통합 |
| LLM의 해석 오류 | 잘못된 도구 선택이나 문장 생성 가능 | 수치는 코드로 계산하고 검증 단계에서 대조 |
| 외부 LLM API 장애 | 신규 질문 분석 불가 | 자동 재시도 후 오류 안내, 저장된 예시 결과 제공 |
| 데이터 갱신 시차 | 최신 추세 반영 지연 | 보고서에 데이터 기준 기간을 표시 |

| 활용 방안 | 대상 | 운영 방식 |
