# 변경·검증 기록

작성일: 2026-11-19. 사용자 제공 기획서의 1~7장 순서를 따릅니다.
원본 기획서는 [user-proposal.md](user-proposal.md), 구현 반영본은 [proposal.md](proposal.md)입니다.

## 1. 구현 목표

현재 목표는 합성 데이터 데모를 검증하고, 실제 데이터와 실행 결과를 혼동하지 않는 제출 문서를 만드는 것입니다.
필수 데이터 활용 완료, 실제 Claude 성능 목표 달성, 센터 PC 검증은 아직 완료로 표시하지 않습니다.

## 3. Agent 개발 구성

- 주 웹 앱: FastAPI와 Chart.js. 보조 검증 앱: Streamlit.
- 이번 수정: Streamlit의 API 키 저장 후 rerun에서 비밀 입력칸에 이전 값이 남는 현상.
- 재현: tests/test_streamlit_ui.py의 입력칸 초기화 검증 실패.
- 조치: 저장·삭제 시 입력 위젯 버전을 갱신하여 비밀 입력값을 다시 표시하지 않음.
- 테스트 수정: 저장값을 검사할 때 목 함수 대신 원래 설정 로더를 사용.
- 결과: 가짜 키 저장, Claude 모드 전환, 비밀 입력칸 초기화, 파일 저장 검증 통과.
- 실제 Claude 호출은 하지 않았음.

## 4. 데이터 활용 계획

| 확인 항목 | 결과 | 의미 |
| --- | --- | --- |
| 월간 API | HTTP 200, 5행, totCnt=335, hasMore=true | 해당 조회 조건의 일부 응답 확인 |
| 요일별 API | HTTP 403 | 권한·프로젝트 등록 등을 확인해야 함, 원인은 확정하지 않음 |
| 필수 항목 | 지역·업종·인구집단·월·이용자·횟수·금액 확인 | 전체 기간 또는 데이터 품질 보증 아님 |
| 실데이터 전체 수집 | 이번 작업에서 미수행 | API 응답 확인과 분석 실적 구분 |
| 임시 조회 코드 | 조회 완료 후 제거 | 앱·원본 파일에 반영하지 않음 |

키는 로컬 .env에서 읽었으며 요청 URL·키·원본 응답 전체를 로그 또는 GitHub에 올리지 않았습니다.
기존 수집 스크립트까지 삭제한 것은 아닙니다. “롤백 완료”는 이 세션이 만든 일회성 확인 코드 제거를 뜻합니다.

명세상 주 데이터에는 별도 테마 필드가 없습니다. 현재 수집 코드의 marketType을 테마와 업종에 함께 매핑하는 처리는 독립 테마 데이터의 확보가 아닙니다.
요일별 dtYearMonth와 dtWeek는 월·요일 집계이며 개별 날짜 거래를 뜻하지 않습니다.

## 5. 개발·탑재 계획

API 확인 전 GitHub 복구 지점은 d53ca2da2b1c2df8e32dc5c1cfb6ea8455cdbacb입니다.
이후 다른 작업에서 제출 패키징 커밋 d927900 및 추가 개발 변경이 관찰되었습니다.
이 세션은 그 변경을 reset하거나 덮어쓰지 않고 담당 파일만 수정했습니다.

동시 변경 중인 주 웹 앱의 src/server.py에는 시작 시 ensure_hub_data를 호출하는 코드가 관찰되었습니다.
사용자의 “임시 확인 후 되돌리기” 요청과 충돌할 수 있어 이번 검증에서는 주 서버를 실행하지 않았습니다.
자동 수집 코드는 별도 담당자와 합의·검토가 필요하며 이번 변경에 섞어 커밋하지 않습니다.

센터 PC에서 직접 실행한 결과는 없습니다. Python 3.14 로컬 환경에서만 테스트했습니다.

## 6. 검증, 한계 및 센터 활용 방안

| 실행 | 결과 |
| --- | --- |
| Python 전체 테스트 | 최종 141 passed, 9.62초 (앞선 실행 133 passed) |
| 정적 데모 JavaScript 테스트 | 6 passed |
| 기획서 목차·HTML 표·상대 링크·상태 표기 | 4 passed |
| 수정 Python 파일 편집기 진단 | 오류 없음 |
| 실제 LLM·유료 API 평가 | 미실행 |
| 인쇄 페이지·센터 PC 검증 | 미실행 |

Python 실행은 외부 소켓 연결을 차단하고 로컬 loopback 연결만 허용했습니다.
재현 명령은 `.venv\Scripts\python.exe scripts\check_offline.py`입니다. 이 실행기는 외부 DNS도 차단하며 현재 Python 프로세스에만 적용됩니다.
실제 환경변수 키는 테스트 프로세스에서 빈 값으로 덮어쓰고, API 검증은 가짜 응답·임시 파일을 사용했습니다.
네트워크 차단으로 Windows 내부 통신까지 막혔던 초기 실패와, 테스트 임시 폴더 누락은 검증 환경 설정 문제로 분리하여 바로잡았습니다.
최종 통과 수는 동시 개발 변경이 포함된 로컬 작업 트리 기준이며 실제 Claude의 질문 정확도나 실제 데이터 정확도가 아닙니다.

추가 확인: 기존 평가 스크립트의 “질문 조건 추출 정확도”는 일부 필드만 확인하고 기간까지 모두 평가하지 않으며,
“도구 선택 정확도”는 실제 도구 호출 일치가 아니라 규칙의 intent 분류 일치입니다.
또 “원본 재계산 검증 통과율”은 경고를 포함한 실패 없음 판정입니다. 엄밀한 목표 달성 지표와 구분해야 합니다.
