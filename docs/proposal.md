# 01 · 제주 관광 소비 인사이트 Agent

## JEJU SIGNAL — 숫자에서 시작하는 더 나은 선택

제주 관광 소비 데이터를 자연어로 탐색하고, 계산 근거를 포함한 분석 보고서로 연결하는 소상공인·센터 이용자용 분석 서비스.

- 참가자·팀명: [제출 전 입력]
- 작성일: 2026년 11월 19일
- 문서 성격: 공모전 기획서 초안 / 12페이지 구성
- 현재 산출물: 브라우저 실행형 가상 데이터 데모
- 필수 데이터 활용 상태: 실데이터 미확보, 허브·센터 등재 및 필수 데이터 인정 여부 미확인

본 기획서는 구현된 기능과 향후 계획을 구분한다. 가상 데이터 결과를 실제 제주 관광 소비 통계로 제시하지 않는다. 제출 전 실제 데이터 분석과 필수 데이터 활용 증빙을 보완해야 한다.

# 02 · 문제 정의와 대상 사용자

## 데이터는 있지만, 의사결정까지의 과정은 복잡하다

소상공인과 센터 이용자는 지역·연령·업종에 따른 소비 변화를 알아보기 위해 데이터를 찾고, 컬럼을 해석하고, 조건을 맞춰 집계해야 한다. 이 서비스는 이러한 반복적인 분석 과정을 지원한다. 해당 수요는 기획 가설이며 사용자 인터뷰로 검증할 예정이다.

- 소상공인: 고객층에 맞춘 월별 소비 흐름과 프로모션 검토 시기를 파악한다.
- 센터 이용자: 조건별 분석 결과와 근거 표를 빠르게 확인한다.
- 행정·상권 지원 담당자: 분석 조건과 출처가 남는 브리핑 초안을 확보한다.

대표 질문: “2025년 서귀포시 30대 관광객의 음식점 소비를 분석하고 프로모션 시기를 제안해 줘.”

해결 범위는 소비 데이터의 탐색·집계·설명이다. 매출 예측, 개별 점포의 수익 보장, 프로모션 인과효과 측정은 범위에 포함하지 않는다.

# 03 · 구현 목표와 평가 기준

## 분석 결과를 계산과 출처로 추적할 수 있게 한다

- 목표 1: 질문에서 지역·연령·업종·기간을 추출하고 부족한 조건은 사용자에게 확인한다.
- 목표 2: 조건에 맞는 데이터를 선택하고 월별 금액·순위·전년 대비 증감을 코드로 계산한다.
- 목표 3: 결측·중복·비교 가능성을 점검하고 계산 근거와 한계를 함께 출력한다.
- 목표 4: 센터 PC에서 고사양 모델 설치 없이 실행 가능한 경량 UI를 제공한다.

검증 기준은 계산 정확성, 조건 보존, 데이터 출처 추적, 실패 시 설명 가능성이다. 금액 집계는 수작업 정답 fixture와 대조하고, 전년 비교는 동일한 조건의 전체 비교 기간이 존재할 때만 허용한다.

현재 검증 대상은 합성 데이터 기반 계산 로직이다. 실데이터의 정확도, 실제 사용자 만족도 및 센터 PC에서의 성능 수치는 아직 측정하지 않았으며 성과로 주장하지 않는다.

# 04 · 서비스 구성과 사용자 경험

## 질문 → 조건 확인 → 분석 → 근거 확인 → 보고서 저장

1. 사용자가 자연어로 분석 질문을 입력한다.
2. 시스템이 해석한 조건을 선택창에 표시한다.
3. 누락된 지역·연령·연도는 사용자가 보완한다.
4. 조건을 확인하고 실행하면 금액·최대 소비 월·전년 대비 변화를 표시한다.
5. 월별 차트와 정확한 수치 표를 함께 확인한다.
6. 판단 및 검증 로그를 읽고 Markdown 보고서를 저장한다.

데모 UI는 질문 입력, 분석 조건, 지표 카드, 월별 차트, 인사이트, 판단 로그로 구성한다. 모바일 화면에서는 한 열로 재배치하며 가상 데이터 표시를 항상 노출한다.

질문이나 조건이 변경되면 이전 결과를 숨겨 서로 다른 분석 조건을 혼동하지 않도록 한다. 요일·시간대 등 미지원 질문은 경고하고 연간 월별 분석을 별도 선택하도록 안내한다.

# 05 · 데이터 활용 계획

## 후보 데이터와 현재 확인 상태

- 월간 내국인관광객 카드 사용 정보: https://www.data.go.kr/data/15056636/openapi.do
- 관광지 및 상업지구 요일별 카드 데이터: https://www.data.go.kr/data/15094893/openapi.do

월간 데이터의 기준연월·지역·연령·업종·금액은 사용자 제공 설명에 따른 후보 항목이다. 원본 스키마, 금액 단위, 집계 정의, 제공 기간, 이용조건은 취득 시 확인한다. 이번 작업에서 해당 상세 페이지는 정상적으로 읽지 못했다.

요일별 데이터는 공공데이터포털 설명에서 날짜·지구·요일·이용자수·이용횟수·이용금액 항목과 이용허락범위 제한 없음 표기를 확인했다. 원본 데이터는 아직 취득하지 않았으며, 제공 범위와 누락·비식별 처리 방식은 별도 확인한다.

공공데이터포털 등재만으로 대회 필수 데이터 요건을 충족했다고 판단하지 않는다. 제주데이터허브·제주빅데이터센터의 해당 데이터 페이지와 필수 데이터 목록 대조 결과를 제출 전 첨부한다.

현재 데모 데이터는 자체 생성한 2024–2025년, 2개 지역, 5개 연령, 3개 업종의 720개 월별 집계 행이다. 실제 데이터를 가공한 것이 아니며 필수 데이터 사용 실적으로 계산하지 않는다.

# 06 · 수집·전처리·분석 설계

## 데이터의 단위와 의미를 먼저 맞춘다

1. API 또는 내려받은 파일의 취득 시점·출처·이용조건을 기록한다.
2. 기준연월, 시군구, 연령, 업종, 금액 컬럼을 내부 스키마에 매핑한다.
3. 금액 단위와 관광객 분류 기준을 확인하고 중복 집계 키를 검사한다.
4. 결측, 비식별 마스킹, 실제 0원을 구분한다. 결측을 0원으로 대체하지 않는다.
5. 동일 조건으로 월별 금액을 합산하고 비교 가능한 경우에만 전년 대비를 계산한다.
6. 원본 합계와 월별 합계를 대조하고 결과에 적용 조건을 표시한다.

월간 연령별 데이터와 요일별 지구 데이터는 집계 차원이 다를 수 있다. 공통 키와 모집단 일치가 검증되지 않으면 결합하지 않고 별도 분석한다. 요일별 자료만으로 “30대가 선호하는 요일”을 추론하지 않는다.

월별 이용자 수는 같은 사람의 중복 가능성이 있으므로 단순 합산한 수치를 연간 고유 관광객 수로 표현하지 않는다. 현재 데모는 금액만 집계한다.

# 07 · Agent 구조와 Workflow

## 판단과 계산을 분리하는 구조

사용자 질문 → 조건 해석 → 필수 조건 확인 → 데이터·도구 선택 → 코드 집계 → 품질 검증 → 근거 기반 보고서.

현재 데모: 한국어 키워드 기반 조건 해석 → 사용자 확인 → 합성 월별 데이터 선택 → JavaScript 집계 → 검증 → 고정 템플릿 보고서.

향후 AI Agent: LLM이 질문을 구조화된 분석 요청으로 변환한다. 허용된 데이터 조회·월별 집계·비교 도구만 호출하며, 수치 계산은 모델이 아닌 분석 코드가 수행한다. 최종 설명은 검증된 수치와 출처만 입력받아 생성한다.

- 조건 해석 도구: 지역·연령·업종·기간 및 지원하지 않는 요구를 구분한다.
- 분석 도구: 필터 적용, 월별 합계, 순위, 전년 대비 계산을 수행한다.
- 검증 도구: 중복·결측·비교 조건·합계 일치 여부를 확인한다.
- 보고서 도구: 수치 표, 차트, 조건, 출처, 한계, 실행 가설을 묶는다.

데모는 LLM을 호출하지 않는 워크플로 프로토타입이다. 이를 실제 LLM 기반 Agent 구현 완료로 표현하지 않는다.

# 08 · 자율 판단과 사용자 통제

## 자동으로 할 일과 확인받을 일을 구분한다

자동 수행 범위: 지원 키워드 해석, 선택 조건에 따른 집계, 순위 계산, 데이터 완전성 검사, 결과 파일 생성.

사용자 확인 범위: 누락 조건 입력, 지역·연령·기간 변경, 더 넓은 범위의 재분석, 미지원 질문을 월별 분석으로 전환하는 선택.

중단 또는 보류 조건: 자료 없음, 중복 키, 음수·비정상 금액은 분석 중단. 비교 기간 불완전 또는 전년도 금액 0원은 증감률 보류. 현재 연도 월별 세부 조건이 불완전하면 시기 제안 보류.

향후 LLM은 임의 코드를 실행하거나 확인 없이 외부 서비스에 데이터를 전송하지 않는다. 사용 가능한 도구와 입력 스키마를 제한하고 원본 데이터의 설명문을 시스템 지시로 취급하지 않도록 설계한다.

현재 출력 로그는 규칙·조건·도구 실행·검증 결과의 기록이다. 모델 내부 사고 과정이나 실행되지 않은 자율 추론을 기록한 것으로 설명하지 않는다.

# 09 · 기술 환경과 센터 탑재

## 현재 데모는 브라우저만으로 실행

- 실행 기술: HTML, CSS, JavaScript. 런타임 외부 라이브러리 없음.
- 실행 방법: demo/index.html을 브라우저로 연다. 인터넷·API Key·GPU 불필요.
- 데이터: 브라우저 메모리에서 합성 데이터를 생성한다. 사용자 입력 외부 전송 없음.
- 테스트: Node.js의 내장 테스트 러너를 사용한다. 데모 실행 자체에는 Node.js가 필요 없다.

센터 최소사양은 공고 제공 기준 Intel Core i7-8700, GTX 1060, RAM 32GB, VRAM 3GB이다. 현 데모는 GPU 연산을 사용하지 않지만 해당 장비에서의 직접 구동 검증은 미실시 상태이다. 운영체제·브라우저·보안 정책도 설치 전 확인한다.

향후 외부 LLM 연동 시 서버 측에서 Key를 관리하고 네트워크·비용·모델명·버전·평가 기간 한도를 매뉴얼에 명시한다. 사용할 모델과 공급자는 미정이다. 데이터 API Key는 제출물에서 제외하며, 외부 AI API 평가용 Key는 공고의 예외 규정에 따라 심사위원용 매뉴얼 영역에서 취급한다.

# 10 · 구현 현황·역할·완성 계획

## 구현 완료와 제출 전 보완을 명확히 분리

현재 구현: 질문 입력 UI, 지원 키워드 해석, 조건 보완, 월별 금액 차트·표, 순위·전년 대비, 계산 검증, 판단 로그, 보고서 다운로드.

미구현: 실데이터 취득·연동, 실제 필수 데이터 증빙, 외부 LLM 기반 도구 선택·설명 생성, 요일별 분석, 실제 운영 환경 검증.

- 기획·도메인 담당: 문제 정의, 분석 질문, 사용자 시나리오 검토. 담당자 [입력].
- 데이터·검증 담당: 출처·이용조건 확인, 스키마 매핑, 집계 검증. 담당자 [입력].
- Agent·UI 담당: 모델·도구 연결, 화면, 실패 처리, 실행 매뉴얼. 담당자 [입력].
- 개인 참가 시 위 역할을 참가자 1인이 수행하며 이름과 실제 수행 범위를 기재한다.

제출 전 우선순위: 필수 데이터 확인·확보 → 실제 분석 재현 → AI 모델 선택 및 연동 → 결과·환경 검증 → 제출 문서 및 ZIP 정리. 이 작업은 일정상 완료를 보장하는 약속이 아니라 남은 작업 목록이다.

# 11 · 검증 방법과 한계

## 재현 가능한 계산부터 검증

테스트에는 조건 누락, 미지원 기간·요일, 수작업 금액 fixture, 전년도 자료 없음, 누락 월, 중복·음수 금액을 포함한다. 테스트 명령은 node --test tests/analysis.test.cjs이다. 수행 결과는 실행 기록과 함께 확인한다.

합계 일치는 집계 내부 일관성을 확인할 뿐 원천 데이터 자체의 정확성을 보증하지 않는다. 실데이터 연동 후 제공기관 집계표와 표본 결과를 별도로 대조한다.

알려진 한계: 키워드 해석은 복합 질의·비교 질의·동의어를 폭넓게 지원하지 않는다. 합성 계절 패턴은 실제 계절성을 의미하지 않는다. 카드 데이터는 전체 소비를 대표하지 않을 수 있으며, 카드사·관광객 분류·표본 범위의 영향을 받는다.

프로모션 제안은 검증이 필요한 실행 가설이다. 소비 규모와 광고 효과 사이의 인과관계를 주장하지 않는다. 시간대·요일·연령 등 서로 다른 차원의 자료는 근거 없는 결합을 금지한다.

# 12 · 센터 활용과 제출 준비

## 분석 결과보다 분석 과정을 재사용한다

센터 활용 방안: 이용자 대상 자연어 분석 입문 도구, 지역·업종별 정기 브리핑 초안, 상권 상담용 근거 표 생성, 데이터 품질·출처 확인 교육 자료로 확장한다.

운영 시 데이터 갱신일, 스키마 변경, API 장애, 비용 한도, 분석 실패를 점검한다. 모델이나 데이터가 바뀌면 동일한 검증 질문과 계산 fixture로 회귀 검증한다.

제출 전 작성자 확인: 참가자명, 실제 역할, 필수 데이터 증빙, 실제 모델명·AI 활용 범위, 외부 자원 목록, 이용조건, 실데이터 실행 결과를 보완한다. 현재 초안과 데모만으로 모든 필수 제출 요건을 충족한 것은 아니다.

출처: 사용자 제공 공모전 규칙(2026.11.10 업데이트 표기), 공공데이터포털 후보 데이터 상세 페이지 2종. 요일별 데이터 페이지는 2026.11.19 확인. 허브·센터 등재는 미확인.

AI 활용: 본 기획서 초안과 데모 코드는 대화형 AI 코딩 도구의 도움으로 작성했다. 제출자는 사용 도구·모델의 실제 명칭, 작성·검토 범위와 최종 검수 내역을 확정하여 명시한다.
